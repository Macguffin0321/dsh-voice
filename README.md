# dsh-voice

> **源码与已安装副本的关系**：本仓库是源码；profile 里的
> `~/.dsh/profiles/desktop/node_modules/dsh-voice` 是它的**副本**。
> 改完本仓库的文件要重新复制过去（`cp -R lib cordis.patch.yml package.json ~/.dsh/profiles/desktop/node_modules/dsh-voice/`）；
> 浏览器半刷新页面即可，宿主半需要重启应用。

KIMI 式的语音播报插件，为 DeepSeek Harness 的 Web/桌面客户端补上「朗读」这一半：

- **实时播报**——AI 回复还在流式生成时就开始朗读，按句切分、边生成边合成边播放，不用等整段回复结束。
- **每段回复下方的小喇叭**——点击可以重播该条回复（再次点击停止），悬停显示提示。
- **悬浮语音控制台**——可拖动、可收起的浮窗，带 ⏪30 秒 / 播放暂停 / 30 秒⏩ / 停止 / 进度条 / 音色切换 / 自动朗读开关。
- **音色切换**——只列出中文音色（普通话 8 个 / 台湾 3 个 / 粤语 3 个），按语言分组、带性别标注。
  Edge 本身提供 322 个音色，其余语言在列表里没有意义，因此全部过滤掉；系统音色同样只保留中文。

> 版本：[v0.3.1](https://github.com/Macguffin0321/dsh-voice/releases) ·
> 许可证 [MIT](LICENSE) · 每次发布都会打 tag，`git checkout v0.3.1` 可以回到任意版本。

## 安装

**不需要构建，也不需要 `pnpm install`** —— 浏览器半的产物 `lib/client.js`
已经在仓库里，克隆下来就是可直接安装的插件。

安装分三步（DSH 桌面端的 profile 由应用独占，不能用 `dsh plugin` 命令写入，
所以这里是直接把目录写进 profile）：

```sh
# 1. 克隆，并放进 profile 的 node_modules
PROFILE="$HOME/.dsh/profiles/desktop"
mkdir -p "$PROFILE/node_modules"

git clone https://github.com/Macguffin0321/dsh-voice.git /tmp/dsh-voice
cp -R /tmp/dsh-voice "$PROFILE/node_modules/dsh-voice"
```

> 只想升级不重装时，`git -C /tmp/dsh-voice pull` 之后再 `cp -R` 覆盖一次即可。
> 覆盖后**浏览器半刷新页面**就生效，**宿主半需要重启应用**。

2. 把 `dsh-voice` 追加到 `~/.dsh/profiles/desktop/package.json` 的
   `dsh.profile.bundles` 数组末尾（**这一步必须有**——profile 只加载
   `bundles` 里列出的包，未列出的会被跳过）：

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "...",
        "dsh-voice"
      ]
    }
  }
}
```

3. 重启 DeepSeek Harness。

重启后打开任意会话，右下角会出现「语音播报」控制台；随便发一条消息，回复会边生成边朗读。
`bundles` 里解析失败或 DSH 版本不兼容的条目会被跳过并在启动日志里列出，
所以启动日志是排查安装问题的第一站。

卸载：把 `node_modules/dsh-voice` 删掉，并从 `bundles` 数组里移除 `dsh-voice`，再重启。

## 语音引擎

| 引擎 | 说明 | 依赖 |
| --- | --- | --- |
| `edge`（默认） | 微软 Edge 神经音色，中文自然度最好，产出 MP3 | `python3 -m pip install --user edge-tts`（需联网） |
| `local` | 系统自带音色：macOS `say`、Windows SAPI、Linux `espeak-ng`，产出 WAV | 无需安装，**离线可用** |
| `browser` | 网页自身的 Web Speech API，不需要宿主合成 | 无（此时进度条只做估算，±30 秒精确跳转不可用） |
| `auto` | 有 `edge-tts` 就用 `edge`，否则退回 `local`，再不行用 `browser` | — |

macOS 上装 `edge-tts`：

```sh
python3 -m pip install --user --break-system-packages edge-tts
```

插件会自动探测 `edge-tts` 可执行文件，找不到时退回 `python3 -m edge_tts`。

## 配置

`cordis.patch.yml` 里的 `voice` 行是**启动基线**；控制台里改的设置在
`~/.dsh/voice-settings.json` 里叠加保存，重启后仍然生效。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关闭后路由返回 503，页面不渲染任何界面 |
| `autoRead` | `true` | 是否自动朗读新的 AI 回复 |
| `readOnSettle` | `false` | 回复结束后是否再完整朗读一遍（关掉就只有流式朗读） |
| `softChunkChars` | `40` | 没有标点时，长句到多少字就切开先读 |
| `maxCharsPerRequest` | `800` | 单次合成请求的字符上限 |
| `engine` | `auto` | `auto` / `edge` / `local` / `browser` |
| `voice` | `''` | 音色 id；留空用引擎默认（edge 为 `zh-CN-XiaoxiaoNeural`，macOS 为 `Tingting`） |
| `rate` | `0` | 语速。edge/local 是百分比增量（-50..50），browser 是绝对倍率 |
| `maxCacheBytes` | `134217728` | 合成音频磁盘缓存上限（LRU 淘汰） |

## 它是怎么工作的

```text
宿主（Node）                                    浏览器（页面）
  agent/assistant-stream ─┐
                          ├─ LiveTextBridge ──▶ /voice/live (WS，失败则轮询)
                          │                        │
  VoiceEngines ◀── POST /voice/segment ──── Reader（分段队列 + <audio> 时间轴）
   edge-tts / say                                │
   磁盘缓存（内容寻址）                            ├─ 小喇叭按钮（回复下方）
   GET /voice/voices                             └─ 悬浮控制台
   GET /voice/status
   POST /voice/settings
```

- **实时文本**：宿主订阅 `agent/assistant-stream`，只转发 `text-delta`（思维链不朗读），
  按 90ms 合并后推给页面；页面用与 `/voice/live` 相同的帧序列号轮询兜底，
  所以宿主解析不到 `ws` 依赖时也能工作。
- **播放**：每个句子是一段独立音频，按顺序在一个 `<audio>` 元素里播放。
  时长由宿主从 WAV/MP3 字节里解析出来，因此进度条和 ±30 秒跳转是真实的媒体时间，
  而不是估算。
- **音色切换**：切了就立刻能听出来。正在朗读的整段会**丢弃已合成的音频、用新音色重新合成**
  （这是必须的——短回复往往在你听完之前就已经全部合成完了，如果只重做「还没合成的部分」，
  你听到的就还是旧音色，看起来像切换没生效）。没有在朗读时切换，则对下一条回复生效。
  浮窗标题右侧的胶囊显示**当前正在听的音色**，控制条上的「重读」可以随时用当前音色重来一遍。
- **重播**：直接读会话事件窗口里的 `assistant/message`（`data.message.content`），
  不重新向模型要文本。

## 开发

```sh
node scripts/build-client.mjs     # 把 client/*.js 打成 lib/client.js（浏览器包）
node scripts/smoke-client.mjs     # 在 stub 环境里跑通整个浏览器半（插槽注册、直播、合成、重播）
DSH_HOME=/tmp/x node scripts/test-host.mjs   # 宿主半测试（时长解析、配置、直播桥、路由）
```

`client/` 是真正的源码，`lib/client.js` 是生成物——改完客户端要重新跑 `build-client.mjs`。

### 两个害人最深的坑（改代码前必读）

1. **音色名是分引擎的词汇表。** Edge 用 `zh-CN-XiaoxiaoNeural` 这种 id，系统语音用
   `Tingting` 这种名字。把前者交给 `say` 不会报错 —— 它会用**系统默认音色**念，
   于是"切音色没反应"看起来像插件没生效。任何"设置了却没效果"的现象，
   先确认**实际发声的是哪个引擎**（`x-voice-engine` / 诊断报告里的"引擎"）。
2. **缓存 key 必须用解析后的值，不能用策略值。** `auto` / `default` 这类策略值一旦进了
   缓存 key，就会让两个不同引擎共用一条缓存 —— 表现是"改了配置毫无变化"，
   而且极难发现，因为所有日志都在说配置已经改了。
3. **响应头回显的是"请求值"，不等于"实际生效值"。** 上面那个 bug 之所以藏了这么久，
   就是因为 `spoke=` 一直显示请求的音色名。判断音色是否真的换了，
   要看 **`fp=`（音频指纹）**，不要看音色名。

### 桌面端的跨源约束（改接口前必读）

桌面客户端的页面来源是 `dsh-app://app/`，服务器是 `http://127.0.0.1:19387`，
**两者不同源**。因此：

- 任何**非简单请求**（自定义 `content-type`、额外请求头、PUT/DELETE…）都会先发
  `OPTIONS` 预检 —— 服务器必须应答，否则浏览器**根本不会发真正的请求**。
- 响应必须带 `access-control-allow-origin`，否则页面读不到结果（连状态码都读不到）。
- 自定义响应头（如 `x-voice-voice`）必须列进 `access-control-expose-headers`。
- 最省事的做法是让它保持**简单请求**：`GET`/`POST` + `text/plain`，零预检。

跨源请求从浏览器发不出去时，表现是 `fetch` 直接 reject 或拿到 405，
而 `curl` 从终端发同一个请求却是 200 —— 这个差异就是判断依据。

### 不重启应用调试

打包好的桌面端把端口写死成 19387，所以第二实例必须换端口。用仓库里的开发启动器
（需要在 Electron 里跑，因为 harness 代码在 `app.asar` 内）：

## 变更记录

> **0.4.2 的教训（值得单独记）**：给 profile 加 `link:` 依赖时，我没有先验证它会怎样影响
> ESM 解析，直接改了你手动搭好的可用配置，**导致插件启动失败（`fail to import`）**。
> 根因是**符号链接会让 Node 用 realpath 解析模块**，于是宿主依赖找不到（详见「安装到
> profile 时的几个坑」）。
>
> 正确的顺序应该是：**先在临时 profile 里验证**再动正式配置 —— 这一点你自己的
> `cordis.patch.yml` 里早就写了（当时是为了排查另一个插件）。教训是**排查方法写了不等于会照做**。


> **0.1.7 的教训（值得记住）**：处理 Markdown 时，**清洗必须在完整文本上做，切句必须在清洗之后**。
> 反过来（先切再洗）会让任何跨行的结构（代码块、表格）在切分处断裂，
> 而"补一条正则"是修不好的 —— 结构已经被切碎了。
> 另一个教训：我在这轮里写了好几个**自己的**调试脚本，它们的 bug 比产品代码还多，
> 浪费了大量时间。**验证要用真实产物**（真实 bundle + 真实的帧序列），不要用手抄的简化版。
>
> **0.1.9 的教训**：**"一次失败就放弃"在语音里是最糟的失败模式。**
> 文字回复失败用户能看见、能重试；语音失败听起来和"说完了"一模一样。
> 所以任何会导致"少读一段"的路径都必须重试，宁可慢一点。
>
> **0.1.8 的教训**：流式处理 Markdown 时，"已到达的部分"和"稳定的部分"不是一回事。
> 表格行、代码围栏这类结构，**在闭合标记到达前都可能是半成品**，
> 而半成品看起来就是普通散文。所以释放边界必须由**结构是否完整**决定，
> 不能由"已经到了多少字"决定。

### 0.3.0

- **修复：同一片段被重复合成 4~5 次，并连带把播放打断。**
  用户诊断报告里两处铁证：

  ```
  17:51:36.060 [fetch] #0 POST ... cached=true      ← 同一个 #0
  17:51:36.060 [fetch] #0 POST ... cached=true      ← 又一遍（同一毫秒）
  17:51:36.075 [media] play() 被拒 #0（被新的加载打断）  ← 9 次 AbortError
  ```

  根因是 `#load` 的**并发去重有一个 await 窗口**：
  `segment.promise` 是在 async 函数**体内**赋值的，而体内第一件事就是 `await`。
  在赋值之前，预取泵（`#pump`）和播放推进（`#advance`）可以同时进入同一个片段，
  各发一次请求。每次请求都会重新设置音频元素的 `src`，
  于是**正在进行的 `play()` 被新的加载打断**（`AbortError`），我 0.2.4 新增的重试又放大了它。
- 修法：把真正的 promise **同步**赋给 `segment.promise`（在第一个 await 之前），
  并在**外层 await 结束后**才释放它 —— 释放点原本在体内，那正是重复请求溜进去的窗口。
- 顺带把元素操作改为幂等：`src` 相同且播放位置已经在开头时不再重新赋值。
- 测试：新增"每段只合成一次"用例，用 30ms 的合成延迟打开竞态窗口。
  已验证：改回体内赋值时该用例**失败**（`[["第一段正文内容，需要念出来。",2]]`），
  同步赋值时通过。212 → 218 项断言。

  > **本轮我犯的错**：第一版修复用一个**占位 promise** 挡住并发，
  > 结果造成**死锁** —— 第二个调用者 await 占位符，而第一个调用者正在处理函数里
  > `await segment.promise`（等它自己的占位符）。测试立刻暴露了它（7 条用例失败）。

## 已知限制

- 宿主半改动需要重启应用；浏览器半改动刷新页面即可（HMR 会重新拉取包）。
- `browser` 引擎没有可寻址的媒体时间轴，进度条是估算值，±30 秒按钮会被禁用。
- 合成是按句并发的（最多 2 路），极长的回复会持续占用 `edge-tts` 子进程直到读完。
- 只朗读助手回复的**正文**。工具调用、思维链不朗读；**代码块和表格整块跳过，连占位提示都不念**
  （早期版本会把代码块念成「代码块」，现在完全跳过）。行内代码保留其文字，因为它属于句子的一部分。
- 路由对跨站来源做了拒绝（只允许同源、`dsh-app://` 与 `file:`），不会变成任意网页可用的合成接口。

## 安装到 profile 时的几个坑

这几条都是踩过之后才明白的，照着做可以省掉几小时。

### 1. 必须用**真实目录副本**，不能用符号链接

```sh
# ✅ 正确
cp -R /path/to/dsh-voice "$PROFILE/node_modules/dsh-voice"

# ❌ 错误：插件会启动失败，报 "Cannot find package '@deepseek-ai/schemastery'"
ln -s /path/to/dsh-voice "$PROFILE/node_modules/dsh-voice"
```

**原因**：Node 的 ESM 解析默认对模块做 `realpath`。符号链接会被解析回源码目录，
于是插件变成"位于 `/path/to/dsh-voice`"，它向上查找 `node_modules` 时找的是**项目目录**——
而 `@deepseek-ai/*` 这些宿主依赖装在 **profile** 里，项目里没有，导入就失败了。

真实副本没有这个问题：文件确实在 `$PROFILE/node_modules/dsh-voice/` 下，
向上走一层就是 `$PROFILE/node_modules/`，宿主的依赖都在那儿。

> 同理，`pnpm` 对 `link:` 依赖创建的就是符号链接，**不要用 `link:` 安装本插件**。

### 2. 想让插件出现在「插件管理器」里，必须写进 `dependencies`

插件管理器的列表**只读 profile 的 `dependencies`**。如果插件只是手动 `cp` 进
`node_modules` 并加进 `bundles`，它能正常工作，但**管理器里看不到、也就没有开关**。

```json
{
  "dependencies": {
    "dsh-voice": "file:../../../project/dsh-voice"
  }
}
```

`file:` 指向插件所在目录（相对 profile 根），写进去之后管理器的开关就出现了。

### 3. 一次性把两处都配对

| 文件 | 需要什么 | 漏了会怎样 |
| --- | --- | --- |
| `package.json` → `dsh.profile.bundles` | 加上 `"dsh-voice"` | 插件**不会被加载**（profile 只加载列出的包） |
| `package.json` → `dependencies` | 加上 `"dsh-voice": "file:..."` | 插件能跑，但**管理器里看不到** |
| `node_modules/dsh-voice/` | 真实目录副本 | 启动报 `ERR_MODULE_NOT_FOUND`
